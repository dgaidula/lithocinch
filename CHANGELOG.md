# Changelog

## 3.3.1 — 2026-10-30
- Fix: where the output volume ignores case, the collision check folded the Turkish dotless `ı` to `i`, so `ılık` and `ilik`, two files on APFS, were refused as one output; both are now written. Applies to the main command and `lithocinch density`.
- Fix: where the output volume is case-sensitive, two outputs whose names differ only in Unicode normalization (`café` written two ways) were both written, and on case-sensitive APFS, which ignores normalization, the second overwrote the first; the later one is now refused (`output collides` under `lithocinch density`, `refused` on the main command). On a volume that keeps the two forms apart (ext4) this refuses a file that could have been written.
- Fix: on HFS+ (Mac OS Extended), two outputs whose names differ only by a code point HFS+ ignores in names (U+200C–200F, U+202A–202E, U+206A–206F, U+FEFF: `ab` with a zero-width non-joiner between the letters against `ab`) or in Georgian `Ⴀ`–`Ⴥ` against `ა`–`ჵ` were both written and the second silently replaced the first, in both commands (3.3.0 too). Where the output volume ignores case, those code points are now dropped and those Georgian letters matched before names are compared, so the later one is refused. This also refuses such pairs on APFS and other case-insensitive volumes, which keep them apart (40 groups in a 70,581-name sample).
- Tests: the dotless `ı`; `ᾴ` precomposed against `ᾳ` plus a combining acute, and `ῷ` against `ῼ` plus a combining perispomeni (NFD, not NFC, before the case fold); case-sensitive APFS, where `Logo.jpg` and `logo.jpg` are both written; and HFS+. The last two make a disk image with `hdiutil` (macOS only, skipped elsewhere; a temp folder already on a case-sensitive volume is used as it is) and detach it when interrupted (SIGINT, SIGTERM) as well as when done.

## 3.3.0 — 2026-10-29
- `--density <ppi>`: after encoding, writes the resolution into JPEG (JFIF, plus EXIF and Photoshop’s resolution resource where present) and PNG (`pHYs`, plus a kept `eXIf`) output by rewriting header bytes only, so it adds no ICC profile or EXIF block: 0 bytes on a PNG, 18 on a JPEG that had no JFIF header. A WebP, AVIF, GIF or TIFF target (`--format`, `--emit`) is a usage error (exit 2); `--format auto` narrows its pool to JPEG and PNG; a file whose own format cannot hold it is written as usual and reported (`density` in the `--json` summary, a warning, a count in the summary). A passed-through original whose XMP resolution is left stale (only with `--allow-stale-xmp`, below) is warned about and counted as stale (`density.stale`, `density.staleFiles`), not as written; outputs skipped because they exist are counted as `skipped (density not checked)`. The value must be plain decimal digits (`0x48`, `1e2` and `72.0` are usage errors).
- `lithocinch density <files-or-folders> --ppi <n>`: new sub-command that rewrites the resolution header of existing JPEGs without re-encoding (decoded pixels and every byte after the header are identical). Refuses a non-JPEG, a damaged or cut-off file (including an EXIF value that points into its own header) and a JPEG that cannot take a JFIF header safely; an XMP resolution is rewritten in place or the file is refused, and with `--allow-stale-xmp` it is a `warn` that names the value and the readers that still see it; other images in a folder are listed as `skip not a JPEG`, and a run with no JPEG exits 1. Inputs that would write the same output are refused `output collides`: the first in argument order keeps it. Where the output volume ignores case this covers names that differ only in case, by a full case fold (`Straße`/`Strasse`, `µ`/`μ`) or in Unicode normalization; `--overwrite` does not override it. Writes via a temporary file and a rename; SIGINT and SIGTERM remove the temporary files in flight (exit 130, 143). Human, `--brief`, `--json` and `--quiet` output; `--dry-run`; exit 0/1/2/3.
- A JPEG whose Adobe APP14 marker says transform 1 over three components (Photoshop’s Save for Web) now gets the JFIF header, with decoded pixels unchanged, under `lithocinch density`, `patchJpegDensity` and `--density` on a passed-through original. Other APP14 shapes are still refused by `lithocinch density`; under `--density` they are written without the density and reported as not applied.
- Library: `patchJpegDensity`, `patchPngDensity`, `readJpegDensity`, `readPngDensity`, `DensityError`; `optimizeImageBuffer` accepts `density` and returns `result.density`.
- XMP resolution (`tiff:`/`exif:` `XResolution`, `YResolution`, `ResolutionUnit`, as an attribute or a plain element) is rewritten in place under `--density` and `lithocinch density`: values keep their form (*n*/1 or *n*; a unit stored as the word `Inch` or `Centimeter` becomes `Inch`), the unit becomes inches, and the length difference comes out of the packet’s trailing padding, so the APP1 segment keeps its length. Only the image’s own properties are rewritten: the same name in a comment, inside another attribute’s value or in a nested resource (`xmpMM:Pantry` and the like) is left as it is. A packet without the padding, Extended XMP, a read-only (`end="r"`) or UTF-16 packet, a name with no namespace prefix, markup that cannot be followed, or any other form is refused (`DensityError` code `stale-xmp`; on the main command the output is not written, it is counted under `refused` and the run exits 1). New `--allow-stale-xmp` (`allowStaleXmp`) writes such files with the old value and a warning instead; the run still exits 1. Apple ImageIO (Preview, Finder) reads XMP before JFIF, so this is what makes Preview show the new number.
- Fix: two sources that would write the same output (`a.gif`, `a.png` and `a.webp` under `--format jpeg`, or a primary and another file’s `--emit` sibling) raced, and the last writer won at random. With a fixed `--format` they are now settled before any job starts: the first in sorted order (primaries before siblings) keeps the path and the later ones are refused (`refused`, `refusedFiles` in `--json`, a `refused` summary line, exit 1). On a volume that ignores case (the macOS and Windows default) names that differ only in case, including a full case fold (`Straße`/`Strasse`), collide too. Under `--format auto` an output name is known only after encoding, so the first file written keeps it and the later one is refused; which file that is can differ between runs.
- Fix: `--json` exited 0 when a file failed; it now exits 1, as without `--json`.
- Fix: `lithocinch transform` printed a stack trace for a bad option (`--format bogus`, a bad `density`, unparsable JSON); it now prints one `error: …` line and exits 2 (1 for a failure while transforming). Option errors, and a request with no `image`, are a `ConfigError` (a subclass of `Error`).
- `sharp` is pinned to exactly 0.35.2.
- Fix: the root of `package-lock.json` now matches `package.json` (name `lithocinch`, licence Apache-2.0, its `bin` entries; it said `process-images`, MIT); every dependency entry is unchanged.

## 3.2.0 — 2026-10-19
- `--cheat` added: `lithocinch --cheat` (and `litho --cheat`) prints a short card of common invocations in tldr page format and exits 0. It cannot be combined with `--json` or `--quiet` (usage error, exit 2).

## 3.1.2 — 2026-10-19
- Fix: a usage error on the directory command (an unknown option, a bad `--format` choice) exited 1, the same status as a failed run; it now exits 2, like `serve` and `transform`. Help and `--version` still exit 0.
- Fix: the `serve` banner said `process-images serve`; it now says `lithocinch serve`.

## 3.1.1 — 2026-10-19
- Fix: `lithocinch transform --help` / `serve --help` (and `-h`) crashed with an `ERR_PARSE_ARGS_UNKNOWN_OPTION` stack trace; they now print the sub-command’s help and exit 0, and an unknown or malformed option is a one-line usage error (exit 2).
